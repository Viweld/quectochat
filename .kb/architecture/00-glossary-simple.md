# Глоссарий простыми словами

Шпаргалка по терминам архитектуры для разработчика уровня junior–middle. Слева — умное слово из документов, справа — что это на практике в QuectoChat.

## Архитектура и DDD

| Термин | Простыми словами |
|--------|------------------|
| **DDD (Domain-Driven Design)** | Подход, где код разложен по «областям бизнеса» (авторизация, контакты, переписка), а не по техническим слоям вперемешку. |
| **Clean Architecture** | Правило «кто на кого может ссылаться»: UI → domain, а domain ни о ком не знает. Меньше связей — легче менять. |
| **Bounded context (ограниченный контекст)** | Смысловая область приложения: «Auth», «Home/Contacts», «Chat». Внутри свои модели и правила. Можно читать как «крупный модуль/тема». |
| **Ubiquitous language (единый язык)** | Договорённость называть вещи одинаково в коде, документах и разговоре: собеседник = `Interlocutor`, сообщение = `Message`. |
| **Domain (`domain/`)** | Пакет с «чистыми» моделями и интерфейсами (контрактами). Без Flutter, без Firebase SDK, без сети. |
| **Data (`data/`)** | Пакет, который реально ходит в Firestore/Firebase Auth и превращает transport-данные в доменные модели. |
| **Feature (`features/*`)** | Экран(ы) + их логика (BLoC) + виджеты одной задачи. |

## Классы и паттерны

| Термин | Простыми словами |
|--------|------------------|
| **Repository (репозиторий)** | Класс-«кладовщик»: «дай список собеседников», «отправь сообщение». Прячет, откуда данные — Firestore или кэш. |
| **Contract / interface (контракт)** | Описание «что умеет» класс, без реализации. Лежит в `domain`. Пример: `ChatRepository`. |
| **`Impl`** | Реализация контракта в `data`. Пример: `ChatRepositoryImpl`. |
| **BLoC** | «Мозг экрана»: принимает события от UI, меняет состояние, командует репозиториями. Без кнопок и навигации внутри. |
| **State (состояние)** | Данные, которые сейчас показывает экран (загрузка, список, ошибка). |
| **Event (событие)** | «Что сделал пользователь»: нажал кнопку, ввёл текст. |
| **Effect (эффект)** | Разовое действие: показать диалог, перейти на другой экран, показать тост. UI ловит эффект и выполняет. |
| **DTO / transport-модель** | Данные «как лежат в Firestore» или «как приходят из SDK». Живут в `data`, наружу не выпускаются. |
| **Mapper (маппер)** | Переводчик transport → доменная модель. Пример: `_MessageMapper` в `features/chat/lib/data/`. |
| **DI (get_it / injectable)** | «Автосборка» зависимостей: не создаём классы руками, просим их у контейнера (`appLocator`). |
| **Port (StatePort / EventPort)** | Узкий cross-feature контракт: прочитать статус auth или сообщить о logout. См. ADR-010, ADR-014. |
| **AppNavigator** | Порт навигации: features и shell не вызывают router напрямую. Реализация — `AppRouter implements AppNavigator` в `navigation/`. |

## Обработка ошибок

| Термин | Простыми словами |
|--------|------------------|
| **`Outcome<S, F>` (Success / Failure)** | Ответ репозитория «получилось / не получилось по бизнес-причине» (неверный пароль, email занят). Ожидаемый исход, не краш. |
| **`ApiException` / network exceptions** | Техническая поломка: нет сети, ошибка Firebase. Обрабатывается отдельно. |
| **`BlocErrorHandler`** | Общий обработчик технических ошибок: показывает тост, репортит. BLoC не делает это сам. |
| **inline-ошибка** | Сообщение прямо под полем/на экране (например, «Неверный пароль»), а не всплывашка. |

## Домен QuectoChat

| Термин | Простыми словами |
|--------|------------------|
| **`AuthStatus`** | Авторизован пользователь или нет (`authorized` / `notAuthorized`). |
| **`Interlocutor`** | Собеседник в списке чатов: id, имя, фамилия, превью последнего сообщения. |
| **`Message`** | Сообщение в переписке: текст, автор, время, тип контента. |
| **`MessageContentType`** | Тип содержимого сообщения (текст, файл и т.д.). |
| **`Paginated<T>`** | Порция данных с пагинацией (список + признак «есть ещё»). |
| **`UserDetails`** | Данные пользователя при регистрации/профиле (имя, email). |

## Навигация

| Термин | Простыми словами |
|--------|------------------|
| **`AppRouter`** | Единый плоский стек auto_route: splash → login/registration → home → chat. |
| **`AuthGuard` / `GuestGuard`** | Охраняют маршруты: неавторизованных — на login, авторизованных с guest-экранов — на home. |
| **`AuthStatusReevaluateListenable`** | Слушает `authStatusStream` и заставляет guards пересчитать маршруты при login/logout. |
